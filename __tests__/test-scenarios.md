## ✅ 셀렉터/검증 가이드 (현 테스트 코드 기준)

### 셀렉터 우선순위

- **접근성 기반 selector (role, name)** ⭐⭐⭐⭐⭐
  - 예: `getByRole('button', { name: '등록' })`, `getByRole('link', { name: '서비스게시판' })`
- **텍스트 기반 selector** ⭐⭐⭐⭐
  - 예: `getByText('삭제')`
- **label / placeholder** ⭐⭐⭐⭐
  - 예: `getByLabel('제목')`, `getByPlaceholder('검색어를 입력하세요')`
- **data-testid** ⭐⭐⭐ (가능하면 지양)
- **CSS / DOM 구조 selector** ❌ (최후의 수단)

### 검증 원칙

- **스타일 값(opacity, z-index 등) 직접 검증은 지양**: 구현/테마에 따라 flaky해지기 쉬움
- **사용자 관점의 동작을 검증**: “표시/숨김”, “클릭 가능/불가”, “포커스 이동/ESC로 닫힘”, “외부 클릭 시 닫힘” 등

## 1. 기본 페이지 및 레이아웃 구성

### TC-001: 기본 레이아웃 요소 표시 확인

**목적**: 홈 페이지 접속 시 GNB, LNB, 콘텐츠 영역이 올바르게 표시되는지 확인

**시나리오**:

1. 사용자가 홈 페이지(`/`)에 접속한다
2. GNB(상단 네비게이션 바)가 표시되는지 확인한다
3. LNB(좌측 네비게이션 바)가 표시되는지 확인한다
4. 콘텐츠 영역이 표시되는지 확인한다

**검증 사항**:

- GNB, LNB, 콘텐츠 영역이 모두 표시됨

---

### TC-002: LNB 메뉴 아이템 표시 및 활성화 상태

**목적**: LNB 메뉴 아이템이 올바르게 표시되고 현재 페이지에 맞게 활성화되는지 확인

**시나리오**:

1. 사용자가 홈 페이지에 접속한다
2. LNB에 "홈", "서비스게시판" 메뉴가 표시되는지 확인한다
3. "홈" 메뉴가 선택된 상태로 표시되는지 확인한다
4. LNB의 "서비스게시판" 메뉴를 클릭한다
5. 서비스 게시판 페이지로 이동하는지 확인한다
6. "서비스게시판" 메뉴가 선택된 상태로 표시되는지 확인한다
7. 다시 LNB의 "홈" 메뉴를 클릭한다
8. 홈 페이지로 이동하고 "홈" 메뉴가 선택된 상태로 표시되는지 확인한다

**검증 사항**:

- LNB 메뉴 아이템이 정확히 표시됨
- 메뉴 클릭 시 올바른 페이지로 이동
- 현재 페이지에 맞는 메뉴가 활성화됨

---

### TC-003: 게시글 상세 페이지에서 LNB 메뉴 활성화 상태

**목적**: 게시글 상세 페이지에서 "서비스게시판" 메뉴가 활성화되는지 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 게시글 제목을 클릭하여 상세 페이지로 이동한다
3. "서비스게시판" 메뉴가 선택된 상태로 유지되는지 확인한다

**검증 사항**:

- 게시글 상세 페이지에서도 "서비스게시판" 메뉴가 활성화됨

---

### TC-004: 게시글 등록/수정 페이지에서 LNB 메뉴 활성화 상태

**목적**: 게시글 등록/수정 페이지에서 "서비스게시판" 메뉴가 활성화되는지 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 등록 버튼을 클릭하여 게시글 등록 페이지로 이동한다
3. "서비스게시판" 메뉴가 선택된 상태로 유지되는지 확인한다
4. 게시판으로 돌아가서 게시글의 더보기 버튼을 클릭하여 수정 페이지로 이동한다
5. "서비스게시판" 메뉴가 선택된 상태로 유지되는지 확인한다

**검증 사항**:

- 게시글 등록/수정 페이지에서도 "서비스게시판" 메뉴가 활성화됨

---

### TC-005: 콘텐츠 영역 스크롤 동작

**목적**: 콘텐츠가 많을 때 콘텐츠 영역에서만 스크롤이 나타나는지 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 게시글이 많아서 스크롤이 필요한 상태를 만든다
3. 콘텐츠 영역에서만 스크롤이 가능한지 확인한다
4. GNB와 LNB는 고정되어 있는지 확인한다

**검증 사항**:

- 콘텐츠 영역에서만 스크롤 가능
- GNB와 LNB는 고정됨

## 3. 홈 페이지

### TC-014: 홈 페이지 이미지 레이아웃 (2x2 배열)

**목적**: 홈 페이지의 이미지가 2x2 배열로 올바르게 배치되는지 확인

**시나리오**:

1. 사용자가 홈 페이지에 접속한다
2. 콘텐츠 영역에 이미지 컴포넌트가 2x2 배열로 배치되어 있는지 확인한다
3. 이미지가 정확히 4개 표시되는지 확인한다
4. 각 이미지의 넓이가 동일한 비율을 가지는지 확인한다
5. 브라우저 넓이에 맞게 조정되는지 확인한다

**검증 사항**:

- 이미지가 정확히 4개 표시됨 (2x2)
- 이미지들이 동일한 비율을 가짐
- 브라우저 넓이에 맞게 조정됨

---

### TC-015: 홈 페이지 보기 타입 전환 (리스트 → 카드)

**목적**: 홈 페이지의 보기 타입을 리스트에서 카드로 전환하는 기능 확인

**시나리오**:

1. 사용자가 홈 페이지에 접속한다 (기본값: 리스트 보기)
2. GNB 우측 아이콘을 클릭한다
3. 드롭다운 메뉴가 노출되는지 확인한다
4. "카드 보기" 옵션을 선택한다
5. 이미지 레이아웃이 카드 형태로 변경되는지 확인한다
6. 브라우저를 새로고침한다
7. 카드 보기 상태가 유지되는지 확인한다 (localStorage 확인)

**검증 사항**:

- 드롭다운 메뉴가 정상적으로 표시됨
- 보기 타입이 올바르게 변경됨
- localStorage에 설정이 저장됨
- 새로고침 후에도 설정이 유지됨

---

### TC-016: 홈 페이지 보기 타입 전환 (카드 → 리스트)

**목적**: 홈 페이지의 보기 타입을 카드에서 리스트로 전환하는 기능 확인

**시나리오**:

1. 사용자가 홈 페이지에 접속한다
2. GNB 우측 아이콘을 클릭하여 "카드 보기"로 전환한다
3. 다시 GNB 우측 아이콘을 클릭한다
4. "리스트 보기" 옵션을 선택한다
5. 이미지 레이아웃이 리스트 형태로 변경되는지 확인한다

**검증 사항**:

- 보기 타입이 올바르게 변경됨
- 리스트 보기 레이아웃이 정확히 표시됨

### 4.2 예외 처리

#### TC-023: 게시글이 없을 때 빈 상태 표시

**목적**: 등록된 게시글이 없을 때 적절한 메시지가 표시되는지 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 모든 게시글을 삭제한다 (또는 빈 상태의 게시판을 확인한다)
3. "등록된 게시글이 없습니다"와 같은 적절한 메시지가 표시되는지 확인한다

**검증 사항**:

- 빈 상태 메시지가 표시됨

---

#### TC-024: 로딩 상태 표시

**목적**: API 요청 중 로딩 상태가 올바르게 표시되는지 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 네트워크 속도를 느리게 설정한다 (개발자 도구)
3. 페이지를 새로고침한다
4. 로딩 인디케이터가 표시되는지 확인한다
5. 데이터가 로드되면 로딩 인디케이터가 사라지는지 확인한다

**검증 사항**:

- 로딩 상태가 표시됨
- 데이터 로드 후 로딩 상태가 사라짐

---

#### TC-025: 에러 상태 표시

**목적**: API 요청 실패 시 에러 상태가 올바르게 표시되는지 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 네트워크를 오프라인으로 설정한다
3. 페이지를 새로고침하거나 검색을 수행한다
4. 에러 메시지가 표시되는지 확인한다

**검증 사항**:

- 에러 상태가 표시됨
- 적절한 에러 메시지가 표시됨

---

2. 기본 레이아웃(GNB, LNB, 콘텐츠 영역)이 표시되는지 확인한다
3. 이미지가 2x2 배열로 표시되는지 확인한다
4. LNB의 "서비스게시판" 메뉴를 클릭한다
5. 서비스 게시판 페이지로 이동하는지 확인한다
6. 게시글 목록을 확인한다
7. 첫 번째 게시글 제목을 클릭한다
8. 게시글 상세 페이지로 이동하는지 확인한다
9. 목록 버튼을 클릭하여 게시판으로 돌아간다

**검증 사항**:

- 전체 흐름이 자연스럽게 동작함
- 각 페이지 간 이동이 정상 동작함

3. 검색 결과가 표시되는지 확인한다

5. 게시글 내용을 확인한다
6. 목록 버튼을 클릭하여 게시판으로 돌아간다
7. 페이징을 통해 다른 페이지로 이동한다
8. GNB 우측 아이콘을 클릭하여 "카드 보기"로 전환한다

**검증 사항**:

### 페르소나 3: 콘텐츠 작성자 (Content Creator)

**특징**: 게시글을 작성하고 관리하는 사용자

#### TC-050: 콘텐츠 작성자의 게시글 작성 및 관리

**목적**: 콘텐츠 작성자가 게시글을 작성, 수정, 삭제하는 전체 흐름 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 등록 버튼을 클릭하여 게시글 등록 페이지로 이동한다
3. 제목과 내용을 입력한다
4. 등록하기 버튼을 클릭한다
5. 게시판으로 이동하고 등록한 게시글이 목록에 표시되는지 확인한다
6. 등록한 게시글의 더보기 버튼을 클릭한다
7. "수정" 옵션을 선택하여 수정 페이지로 이동한다
8. 내용을 수정하고 등록하기 버튼을 클릭한다
9. 수정된 내용이 반영되었는지 확인한다
10. 다시 더보기 버튼을 클릭하여 "삭제" 옵션을 선택한다
11. 삭제 모달에서 삭제 버튼을 클릭한다
12. 게시글이 삭제되었는지 확인한다

**검증 사항**:

- 게시글 작성, 수정, 삭제가 모두 정상 동작함
- 전체 흐름이 자연스럽게 동작함

### 페르소나 4: 고급 사용자 (Power User)

**특징**: 모든 기능을 능숙하게 사용하는 사용자

#### TC-051: 고급 사용자의 복합 기능 사용

**목적**: 고급 사용자가 여러 기능을 복합적으로 사용하는 시나리오 확인

**시나리오**:

1. 사용자가 홈 페이지에 접속한다
2. GNB 우측 아이콘을 클릭하여 "카드 보기"로 전환한다
3. LNB의 "서비스게시판" 메뉴를 클릭한다
4. 검색어를 입력하여 게시글을 검색한다
5. 검색 결과 중 하나를 클릭하여 상세 페이지로 이동한다
6. 상세 페이지에서 더보기 버튼을 클릭한다
7. "삭제" 옵션을 선택하여 삭제 모달을 연다
8. 취소 버튼을 클릭하여 모달을 닫는다
9. 목록 버튼을 클릭하여 게시판으로 돌아간다
10. 페이징을 통해 여러 페이지를 탐색한다
11. 게시글의 더보기 버튼을 클릭하여 드롭다운을 연다
12. "삭제" 옵션을 선택하여 삭제 모달을 연다 (중첩 모달)
13. 삭제 모달의 취소 버튼을 클릭한다
14. 드롭다운만 남아있는지 확인한다 (FILO 방식)
15. 드롭다운도 닫는다

**검증 사항**:

- 모든 기능이 정상 동작함
- 중첩 모달이 FILO 방식으로 동작함
- 복합적인 사용 시나리오가 정상 동작함

### 테스트 데이터 관리

- 각 테스트는 독립적으로 실행 가능해야 함
- 테스트 전후 데이터 초기화 필요
- API 모킹 또는 실제 API 사용 결정 필요
- 테스트 격리: 각 테스트는 다른 테스트에 영향을 주지 않아야 함

### 테스트 작성 시 고려사항

1. **명확한 테스트 이름**: 각 테스트는 무엇을 테스트하는지 명확해야 함
2. **독립성**: 각 테스트는 다른 테스트에 의존하지 않아야 함
3. **재사용 가능한 헬퍼 함수**: 공통 로직은 헬퍼 함수로 분리
4. **적절한 대기 시간**: 비동기 작업에 대한 적절한 대기 처리
5. **에러 처리**: 예외 상황에 대한 적절한 테스트

추가 권장:

6. **셀렉터 우선순위 준수**: `getByRole/name` → `getByText` → `getByLabel/getByPlaceholder` 순으로 작성
7. **DOM 구조/스타일 의존 최소화**: `div > span:nth-child(2)`/opacity 같은 검증은 피하고, 사용자 행동 결과로 검증
