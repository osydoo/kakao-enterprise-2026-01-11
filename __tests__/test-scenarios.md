## ✅ 셀렉터/검증 가이드 (현 테스트 코드 기준)

### 셀렉터 우선순위

- **접근성 기반 selector (role, name)** ⭐⭐⭐⭐⭐
  - 예: `getByRole('button', { name: '등록' })`, `getByRole('link', { name: '서비스게시판' })`
- **텍스트 기반 selector** ⭐⭐⭐⭐
  - 예: `getByText('삭제')`
- **label / placeholder** ⭐⭐⭐⭐
  - 예: `getByLabel('제목')`, `getByPlaceholder('검색어를 입력하세요')`
- **data-testid** ⭐⭐⭐ (가능하면 지양)
- **CSS / DOM 구조 selector** ❌ (최후의 수단)

### 검증 원칙

- **스타일 값(opacity, z-index 등) 직접 검증은 지양**: 구현/테마에 따라 flaky해지기 쉬움
- **사용자 관점의 동작을 검증**: “표시/숨김”, “클릭 가능/불가”, “포커스 이동/ESC로 닫힘”, “외부 클릭 시 닫힘” 등

## 1. 기본 페이지 및 레이아웃 구성

### TC-1-1: 기본 레이아웃 요소 표시 확인

**목적**: 홈 페이지 접속 시 GNB, LNB, 콘텐츠 영역이 올바르게 표시되는지 확인

**시나리오**:

1. 사용자가 홈 페이지(`/`)에 접속한다
2. GNB(상단 네비게이션 바)가 표시되는지 확인한다
3. LNB(좌측 네비게이션 바)가 표시되는지 확인한다
4. 콘텐츠 영역이 표시되는지 확인한다

**검증 사항**:

- GNB, LNB, 콘텐츠 영역이 모두 표시됨

---

### TC-1-2: LNB 메뉴 아이템 표시 및 활성화 상태

**목적**: LNB 메뉴 아이템이 올바르게 표시되고 현재 페이지에 맞게 활성화되는지 확인

**시나리오**:

1. 사용자가 홈 페이지에 접속한다
2. LNB에 "홈", "서비스게시판" 메뉴가 표시되는지 확인한다
3. "홈" 메뉴가 선택된 상태로 표시되는지 확인한다
4. LNB의 "서비스게시판" 메뉴를 클릭한다
5. 서비스 게시판 페이지로 이동하는지 확인한다
6. "서비스게시판" 메뉴가 선택된 상태로 표시되는지 확인한다
7. 다시 LNB의 "홈" 메뉴를 클릭한다
8. 홈 페이지로 이동하고 "홈" 메뉴가 선택된 상태로 표시되는지 확인한다

**검증 사항**:

- LNB 메뉴 아이템이 정확히 표시됨
- 메뉴 클릭 시 올바른 페이지로 이동
- 현재 페이지에 맞는 메뉴가 활성화됨

---

### TC-1-3: 게시글 상세 페이지에서 LNB 메뉴 활성화 상태

**목적**: 게시글 상세 페이지에서 "서비스게시판" 메뉴가 활성화되는지 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 게시글 제목을 클릭하여 상세 페이지로 이동한다
3. "서비스게시판" 메뉴가 선택된 상태로 유지되는지 확인한다

**검증 사항**:

- 게시글 상세 페이지에서도 "서비스게시판" 메뉴가 활성화됨

---

### TC-1-4: 게시글 등록/수정 페이지에서 LNB 메뉴 활성화 상태

**목적**: 게시글 등록/수정 페이지에서 "서비스게시판" 메뉴가 활성화되는지 확인

**시나리오**:

1. 사용자가 게시글 등록 페이지로 직접 이동한다 (URL 이동으로 UI 플로우 의존도 제거)
2. "서비스게시판" 메뉴가 선택된 상태로 유지되는지 확인한다
3. 사용자가 게시글 수정 페이지로 직접 이동한다 (URL 이동으로 데이터/더보기 메뉴 의존도 제거)
4. "서비스게시판" 메뉴가 선택된 상태로 유지되는지 확인한다

**검증 사항**:

- 게시글 등록/수정 페이지에서도 "서비스게시판" 메뉴가 활성화됨

---

### TC-1-5: 콘텐츠 영역 스크롤 동작

**목적**: 콘텐츠가 많을 때 콘텐츠 영역에서만 스크롤이 나타나는지 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 콘텐츠 영역이 표시되는지 확인한다
3. 콘텐츠 영역이 스크롤 가능한지 확인한다 (스크롤 높이가 클라이언트 높이보다 큰지 확인)
4. 게시글이 많아서 스크롤이 필요한 경우, 스크롤이 정상 동작하는지 확인한다

**검증 사항**:

- 콘텐츠 영역이 표시됨
- 콘텐츠 영역에서 스크롤이 정상 동작함

---

### TC-1-6: GNB 우측 보기 타입 dropdown 표시 및 저장

**목적**: GNB 우측 dropdown(보기 타입)을 통해 보기 타입을 변경하고 localStorage에 저장되는지 확인

**시나리오**:

1. localStorage를 초기화한다
2. 사용자가 홈 페이지(`/`)에 접속한다
3. GNB 우측 dropdown 트리거(버튼 텍스트)가 표시되는지 확인한다
4. "카드 보기"를 선택한다
5. localStorage의 `viewType` 값이 `card`로 저장되는지 확인한다

**검증 사항**:

- dropdown 트리거가 표시됨
- "카드 보기" 선택이 정상 동작함
- 선택값이 localStorage에 저장됨 (`viewType=card`)

## 2. 홈 페이지

### TC-2-1: 홈 페이지 이미지 레이아웃 (2x2 배열)

**목적**: 홈 페이지의 이미지가 2x2 배열로 올바르게 배치되는지 확인

**시나리오**:

1. 사용자가 홈 페이지에 접속한다
2. 이미지 그리드가 표시되는지 확인한다
3. 이미지 아이템이 정확히 4개 표시되는지 확인한다 (2x2)
4. 각 이미지의 넓이가 동일한지 확인한다 (약간의 오차 허용)

**검증 사항**:

- 이미지 그리드가 표시됨
- 이미지가 정확히 4개 표시됨 (2x2)
- 이미지들의 넓이가 동일함 (약간의 오차 허용)

---

### TC-2-2: 홈 페이지 보기 타입 전환 (리스트 → 카드)

**목적**: 홈 페이지의 보기 타입을 리스트에서 카드로 전환하는 기능 확인

**시나리오**:

1. 사용자가 홈 페이지에 접속한다
2. 기본값이 리스트 보기인지 확인한다 (이미지 그리드가 표시되는지 확인)
3. 보기 타입 전환 버튼을 클릭하여 "카드 보기"로 전환한다
4. 카드 형태로 변경되었는지 확인한다 (이미지 그리드가 표시되는지 확인)
5. localStorage의 `viewType` 값이 `card`로 저장되었는지 확인한다
6. 브라우저를 새로고침한다
7. 카드 보기 상태가 유지되는지 확인한다 (localStorage 확인)

**검증 사항**:

- 기본값이 리스트 보기로 설정됨
- 보기 타입이 올바르게 변경됨
- 카드 형태로 변경되었는지 확인됨
- localStorage에 설정이 저장됨 (`viewType=card`)
- 새로고침 후에도 설정이 유지됨

---

### TC-2-3: 홈 페이지 보기 타입 전환 (카드 → 리스트)

**목적**: 카드 보기에서 리스트 보기로 전환 시 저장값이 갱신되고 유지되는지 확인

**시나리오**:

1. localStorage를 초기화한다
2. 사용자가 홈 페이지에 접속한다
3. 먼저 "카드 보기"로 전환한다
4. 다시 "리스트 보기"로 전환한다
5. 리스트 형태로 변경되었는지 확인한다 (이미지 그리드가 표시되는지 확인)
6. localStorage의 `viewType` 값이 `list`로 저장되었는지 확인한다
7. 브라우저를 새로고침한다
8. 리스트 보기 상태가 유지되는지 확인한다 (localStorage 확인)

**검증 사항**:

- 보기 타입이 올바르게 변경됨
- 리스트 형태로 변경되었는지 확인됨
- localStorage에 설정이 저장됨 (`viewType=list`)
- 새로고침 후에도 설정이 유지됨

## 3. 서비스 게시판

#### TC-3-1: 서비스 게시판 기본 화면 확인

**목적**: 서비스 게시판 페이지의 기본 레이아웃과 기능 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 검색 입력 필드가 표시되는지 확인한다
3. 검색 버튼이 표시되는지 확인한다
4. 등록 버튼이 표시되는지 확인한다
5. 게시글 테이블이 표시되는지 확인한다
6. "서비스게시판" 메뉴가 선택된 상태로 표시되는지 확인한다

**검증 사항**:

- 모든 필수 UI 요소가 표시됨
- LNB 메뉴 상태가 올바름

---

#### TC-3-2: 게시글 검색 기능 (엔터/버튼)

**목적**: 엔터 키/검색 버튼으로 게시글을 검색하는 기능 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 검색 입력 필드에 검색어를 입력한다
3. 엔터 키를 눌러 검색한다
4. 네트워크 요청이 완료될 때까지 대기한다
5. 게시글 목록이 로드될 때까지 대기한다
6. 검색 결과가 있는 경우, 검색어가 포함된 게시글만 표시되는지 확인한다
7. 검색 입력 필드에 다른 검색어를 입력한다
8. 검색 버튼을 클릭하여 검색한다
9. 네트워크 요청이 완료될 때까지 대기한다
10. 게시글 목록이 로드될 때까지 대기한다
11. 검색 결과가 있는 경우, 검색어가 포함된 게시글만 표시되는지 확인한다

**검증 사항**:

- 엔터 키로 검색 가능
- 검색 버튼 클릭으로 검색 가능
- 검색 결과가 정확히 필터링됨

---

#### TC-3-3: 게시글 목록 클릭하여 상세 페이지 이동

**목적**: 게시글 제목을 클릭하여 상세 페이지로 이동하는 기능 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 게시글이 있는지 확인한다
3. 게시글이 있는 경우, 첫 번째 게시글 제목을 클릭한다
4. 게시글 상세 페이지로 이동하는지 확인한다 (URL 패턴 확인)
5. 게시글 제목과 내용이 표시되는지 확인한다
6. "서비스게시판" 메뉴가 선택된 상태로 유지되는지 확인한다 (aria-current 속성 확인)

**검증 사항**:

- 게시글이 있는 경우에만 테스트 진행
- 게시글 제목 클릭 시 상세 페이지로 이동
- 게시글 정보가 정확히 표시됨
- LNB 메뉴 상태가 올바름

---

#### TC-3-4: 게시글 등록 페이지 이동

**목적**: 등록 버튼을 통해 게시글 등록 페이지로 이동하는 기능 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 등록 버튼을 클릭한다
3. 게시글 등록 페이지로 이동하는지 확인한다 (URL 확인)
4. "서비스게시판" 메뉴가 선택된 상태로 유지되는지 확인한다 (aria-current 속성 확인)

**검증 사항**:

- 등록 페이지로 정상 이동
- LNB 메뉴 상태가 올바름

---

#### TC-3-5: 한 페이지당 최대 데이터 개수 확인

**목적**: 테이블에 한 페이지당 최대 10개의 데이터가 표시되는지 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 게시글 개수를 확인한다
3. 한 페이지당 최대 10개인지 확인한다
4. 게시글이 정확히 10개인 경우, 페이징이 표시되는지 확인한다
5. 페이징이 표시되는 경우, 다음 페이지 버튼이 있는지 확인한다
6. 다음 페이지 버튼이 있는 경우, 다음 페이지로 이동한다
7. 네트워크 요청이 완료될 때까지 대기한다
8. 페이지 번호 버튼이 있는 경우 특정 페이지(예: 2페이지)로 이동한다
9. 네트워크 요청이 완료될 때까지 대기한다
10. 페이지가 정상적으로 전환되었는지 확인한다 (aria-current 속성 확인)

**검증 사항**:

- 한 페이지당 최대 10개의 게시글이 표시됨
- 10개일 경우 페이징이 표시됨
- 페이지 이동이 정상 동작함

---

### 3.2 예외 처리

#### TC-3-6: 게시글이 없을 때 빈 상태 표시

**목적**: 등록된 게시글이 없을 때 적절한 메시지가 표시되는지 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 검색 입력 필드에 존재하지 않는 검색어를 입력한다 (예: `__e2e_empty__${Date.now()}`)
3. 엔터 키를 눌러 검색을 수행한다
4. 네트워크 요청이 완료될 때까지 대기한다
5. 게시글 목록이 비어있는지 확인한다 (게시글 개수가 0개인지 확인)
6. 빈 상태 메시지가 나타날 때까지 대기한다 (최대 5초)

**목적**: 게시글 수정 페이지의 기본 UI와 기존 데이터 표시 확인

**시나리오**:

1. 사용자가 서비스 게시판 페이지에 접속한다
2. 게시글의 더보기 버튼을 클릭하여 수정 페이지로 이동한다
3. 페이지 타이틀에 "게시글 수정"이 표시되는지 확인한다
4. 기존 게시글 제목이 입력 필드에 표시되는지 확인한다
5. 기존 게시글 내용이 입력 필드에 표시되는지 확인한다
6. 등록하기 버튼이 표시되는지 확인한다

**검증 사항**:

- 페이지 타이틀이 올바름
- 기존 데이터가 입력 필드에 표시됨
- 모든 필수 UI 요소가 표시됨

### TC-5-7: 게시글 수정 성공

**목적**: 게시글을 수정하는 기능 확인

**시나리오**:

1. 사용자가 게시글 수정 페이지에 접속한다
2. 제목 또는 내용을 수정한다
3. 등록하기 버튼을 클릭한다
4. 서비스 게시판 페이지로 이동하는지 확인한다
5. 수정한 내용이 반영되어 있는지 확인한다

**검증 사항**:

- 게시글 수정 성공
- 게시판으로 자동 이동
- 수정한 내용이 반영됨
- 상세 페이지에서도 수정된 내용이 표시됨

6. 등록하기 버튼을 클릭한다
7. 유효성 검사 에러 메시지가 표시되는지 확인한다

**검증 사항**:

- 수정 페이지에서도 유효성 검사가 동작함
- 빈 값 입력 시 에러 메시지 표시

## 📝 테스트 실행 가이드

### 사전 준비

1. 개발 서버 실행 (`npm run dev`)
2. 테스트 데이터 준비 (게시글 생성)
3. 브라우저 환경 설정

### 테스트 실행 명령어

```bash
# 전체 테스트 실행
npm run test

# UI 모드로 테스트 실행
npm run test:ui

# 특정 테스트 파일 실행
npx playwright test __tests__/e2e/specific-test.spec.ts

# 특정 테스트만 실행 (태그 사용)
npx playwright test --grep "TC-1-1"
```

### 테스트 데이터 관리

- 각 테스트는 독립적으로 실행 가능해야 함
- 테스트 전후 데이터 초기화 필요
- API 모킹 또는 실제 API 사용 결정 필요
- 테스트 격리: 각 테스트는 다른 테스트에 영향을 주지 않아야 함

--> MSW 등 세팅이 가장 편리하지만 해당 프로젝트에선 제외

### 테스트 작성 시 고려사항

1. **명확한 테스트 이름**: 각 테스트는 무엇을 테스트하는지 명확해야 함
2. **독립성**: 각 테스트는 다른 테스트에 의존하지 않아야 함
3. **재사용 가능한 헬퍼 함수**: 공통 로직은 헬퍼 함수로 분리
4. **적절한 대기 시간**: 비동기 작업에 대한 적절한 대기 처리
5. **에러 처리**: 예외 상황에 대한 적절한 테스트

추가 권장:

6. **셀렉터 우선순위 준수**: `getByRole/name` → `getByText` → `getByLabel/getByPlaceholder` 순으로 작성
7. **DOM 구조/스타일 의존 최소화**: `div > span:nth-child(2)`/opacity 같은 검증은 피하고, 사용자 행동 결과로 검증
